# 星际航运经营游戏

一款以星际客运网络规划为核心的网页经营游戏，目前已经具备可完整游玩的 v0.6 prototype。

玩家先选择一个星球作为公司基地，再从有限资金与一艘客轮开始，通过观察需求与燃料价格、设计航线、配置船只、安排维护和调整票价，在 AI 竞争与市场事件中争取于 120 日内达成初级现金或客流目标。达标后不会结局，可以继续自由经营。

## 当前实现

项目目前由三个部分组成：可独立运行的 TypeScript 日结算模拟核心、可序列化的经营游戏状态层，以及使用 React、Vite 和 SVG 构建的网页游戏界面。

模拟核心已经支持：

- 根据真实起讫星港属性和理论旅行时间，分别生成商务、休闲旅游、廉价、高端四类旅客需求
- 将往返线和环线自动展开为可售服务航段
- v0.5 仅生成单一航线直达候选行程，同时保留数组化航段结构供后续转机版本使用
- 四类旅客分别比较经济、商务、头等三种舱位产品，根据票价、时间、频率、直达性、舒适度、声誉和准点率分配客流
- 生成由真实效用分项驱动的满意与不满意原因，而非固定泛化文案
- 在多个市场之间分配共享航段运力
- 按舱位、方向和旅客类型结算客流与收入；完整成本包含燃料、人员、港口、维护、船龄、折旧与预计延误
- 星际燃料按船体、客舱和携带燃料质量及“光年/(吨燃料·吨船重)”效率结算；亚光速按推力和比冲模拟加速—滑行—减速，忽略旅客质量
- 让航线沿连通网络跨越无人行星系，并验证船型推进方式、航程和港口等级

经营状态层已经支持：

- 有限现金、公司日常开销、购船与航线开办资本支出
- 单船所有权、引擎类型、维护值、累计飞行时间、约 3,200 飞行小时（高利用率下约半年）的维护周期、返抵主基地触发的自动维修阈值与维护停场
- 按“出发地、目的地、出行方式、船只”的顺序创建基地往返航线；同线可混用兼容型号并按各自速度、舱位、周转和可靠性生成实际航班
- 一周模板支持自动均匀或手工五分钟时刻；每艘船具有不可瞬移的连续轮转、当前位置和事件日志
- 星港按等级提供 12/28/60/120/240 个每日 movement 并拆为逐小时时隙；事件、投资和拥堵会修正硬容量
- 五类可复现延误影响后续轮转、满意度、额外成本及全局/本地声誉，取消与 4/12 小时晚点按规则退款
- 随机星域相邻行星系平均距离约 10 光年；星际有效速度上限为 10 光年/日，单个航段仍至少需要一天
- 船况下降不会降低航速，但会降低不同客群的满意度与航线吸引力
- 分别输入三舱数字票价，修改先预测、确认后生效，并可恢复完整成本加 20% 的推荐价
- 按日保留三舱供需、双向上座率、四类旅客、完整成本、评价解释、预测偏差与逐航线经营表现
- 各星港动态燃料价格、最近 30 日价格历史，以及燃料市场冲击事件
- 基地拥有固定 2,500 FU 燃料库，可设置低价自动买满和高价优先取用库存策略
- 三类确定性随机事件、120 日初级目标、达标后自由经营和破产失败条件
- 浏览器本地自动存档，以及刷新后继续游戏

### 本地运行

需要 Node.js `^20.19.0` 或 `>=22.12.0`；推荐使用 Node.js 24。

```bash
npm install
npm test
npm run demo
npm run demo:campaign
```

常用命令：

```bash
npm run check  # TypeScript 类型检查
npm run build  # 编译到 dist
npm test       # 编译并运行情景测试
npm run demo   # 运行三港口示例
npm run demo:campaign # 运行20星港、196日战役示例
```

模拟器的公共入口是 `src/index.ts`，完整日结算入口是 `simulateDay()`。

## 网页界面

网页端默认生成 8 个行星系和 6 个星港。界面可配置 3–24 个行星系，星港总数为 2 至行星系总数；每个有人行星系有且只有一个星港，无人行星系没有星港。底层生成器仍允许单星港场景，网页为确保可经营而要求至少两个。生成器支持可复现种子、星域形状、超空间网络走向和航道密度配置。

当前网页功能包括：

- 一张可拖动、可缩放和重置视角的银河系大图
- 行星系只保留“有人居住”和“无人居住”两类；两类节点使用不同状态环和文字标识
- 有人行星系拥有星港、客运市场和航路，可以点击查看市场；无人行星系没有星港或殖民人口，仅作为银河探索空间展示
- 超空间航路是银河的客观属性，覆盖并连通全部行星系；无人行星系也可以成为航路节点
- 固定在顶部的资金、昨日收入、成本、利润与客流
- 顶部“星图运营 / 舰队管理 / 航线经营”视图；航线详情提供经营、旅客、价格、成本四个子页
- 固定在底部的暂停、倍速和单日推进控制
- 星港人口与发展属性驱动的跨星需求，以及热门市场的额外 AI 竞争航线
- 新游戏时选择初始基地星球；所有玩家航线固定从基地出发
- 为航线选择沿网络运行的超空间航路或点对点直达的曲率航路；地图分别显示实际路径
- 航线预览单程航时、往返周期、每周班次、三舱盈亏平衡价与推荐价；航线列表显示利润、三舱上座率、准点率和预警
- 银河地图按模拟时间逐帧推进船标，跨越航段、停靠和往返周期边界时不会跳回基地，并显示所有玩家船只的当前位置与状态
- 新船以空舱交付；玩家为同一种船型建立多个统一配置方案，按头等/商务/经济每座 6/3/1 空间布置客舱，再批量分配同型舰船
- 航段燃料消耗同时受距离、推进方式、结构与客舱质量、实际载客量和设计航程错配影响；每次出发前自动装载燃料并加入 20% 应急裕度，航线预览显示空载与满载燃料消耗
- 每种型号收取每日固定维护费；同一供应商与同一系列的舰队规模折扣可以乘算叠加，另保留飞行小时维护和定期大修
- 多个型号可加入同一份采购协议，行情折扣与批量协议折扣乘算叠加；订单按热度、吨位和数量排产，低热度型号更容易促销并出现现货
- 舰船按 360 日累计船龄；老船固定维护费上升、舒适度下降，玩家可设定自动更新阈值：到龄后订购同型号新船，交付时继承航线与客舱方案并出售旧船
- 30 种具体型号归入 9 个舰船系列，覆盖支线、快运、商务、卧铺与大型干线定位；购买界面按“系列 → 子型号”二级菜单组织
- 购买与分配不同引擎的客轮，观察维护值、设置返抵主基地后的自动维修阈值、手动维护并处理维护停场；超空间速度整体高于曲率，亚光速指数通过“12 ÷ 指数小时”影响每次星港接驳周转
- 查看所选星港最近 30 日燃料价格曲线和全星域当前价格
- 使用键盘输入并确认三舱票价，查看考虑平行航线与 AI 竞争的价格—客流—利润区间表，暂停/恢复/关闭航线
- 世界事件预告与效果、初级经营目标进度、达标后继续经营、破产反馈和新游戏流程

此前完成的“银河 → 恒星系 → 行星/卫星”三级连续星图和 WebGPU 天体渲染不进入第一版验证，代码与设计说明保留在[技术储备](docs/technical-reserve/three-level-map.md)中。

```bash
npm run dev       # 启动本地开发服务器
npm run build:web # 构建静态网页到 web-dist
```

网页端目前在主线程同步执行单日结算；后续迁移至 Web Worker 后可以进一步提高可生成的行星系规模。
