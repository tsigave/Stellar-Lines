# 星际航运经营游戏：v0.4 至 v0.11 总体版本计划

## 文档目的

当前实现基线为 v0.6.1；下方 v0.4 段落作为历史依赖说明保留。

本目录把当前 v0.4 原型之后的工作拆成可以独立验收的阶段。v0.7 插入标准推进、舰船选装与航程经济重构，原 v0.7–v0.10 依次顺延为 v0.8–v0.11。规划目标不是继续堆叠孤立功能，而是逐步建立完整的星际客运经营闭环：旅客拥有真正目的地并比较完整行程，航司以舰队、时刻、星港容量和基地网络组织供给，玩家与 AI 在相同规则下竞争与合作。

## v0.4 历史基线

v0.4 已经形成以下可玩基础：

- 中文行星系、随机银河、星港、曲率与超空间网络；
- 单基地往返航线、逐日客流与经营结算、基础 AI 竞争航线；
- 经济/商务/头等三种客舱产品与统一配置方案；
- 自动燃料装载、20% 应急裕度、结构质量与航程错配燃料消耗；
- 9 个舰船系列、30 个具体型号、系列与供应商维护折扣；
- 多型号采购协议、随机行情折扣、热度、现货、船厂排产与延期交付；
- 船龄、船况、维护、舒适度衰减、二手估值与交付后自动换新；
- 顶部舰队管理选项卡、右侧星港航线建立区和最低 12px 字体规范。

当前主要限制是：需求仍围绕单段服务表达，票价与收益解释不足，航线难以动态换船，航班没有完整时刻和星港容量竞争，基地只有一个，AI 也没有持续经营决策。

## 最终模型中的核心对象

后续版本统一采用以下概念边界：

| 对象 | 含义 |
|---|---|
| 旅客类型 | 商务、休闲旅游、廉价、高端；描述需求与偏好，不等于舱位 |
| 舱位产品 | 经济、商务、头等；描述容量、价格与服务水平 |
| 真实旅程需求 | 旅客从真实起点到真实目的地的出行需求，与任何具体航线无关 |
| 候选行程 | 由一至三段航班组成，可直飞、同航司转机或跨航司联程 |
| 航班服务 | 在确定日期和时刻执行的一次起降服务 |
| 航线 | 航司对一组市场长期提供的商业产品、价格和班表 |
| 舰船轮转 | 具体舰船依次执行的航班序列，可跨多条航线 |
| 船体子型号 | 定义结构、客舱、燃料舱、安装位和星港限制，不直接包含推进性能 |
| 舰船配置 | 船体、亚光速引擎、曲率或超空间驱动器及辅助模块的可采购组合 |
| 任务质量状态 | 舰船在出港、星际航行、进港各阶段的干质量、燃料与有效载荷 |
| 星港时隙 | 星港在某一时段允许的起飞或降落容量 |
| 基地 | 舰船、人员、维护与调度资源的组织节点，也是航线的可选起飞点 |

这些对象必须分开保存，避免再次把“旅客类型等同舱位”“航线等同具体船只”或“目的地等同下一航段终点”。

## 跨版本统一规则

### 需求与选择

- 旅客需求先按真实 OD 与旅客类型生成，再比较所有可行候选行程。
- 选择因素至少包括总票价、总旅行时间、发班时刻、频率、转机次数、错失衔接风险、舒适度、准点率、航司声誉和舱位可用性。
- “不出行”始终是一个选择，降价可以刺激需求，但不能无限创造旅客。
- 同公司航线会互相分流；AI、玩家和联程伙伴共享同一选择与容量分配规则。

### 成本与收益

- 航线完全成本包含燃料、船员与地勤、港口、飞行小时维护、固定维护、船龄加价、折旧、晚点赔付和跨航司结算。
- 燃料统一以吨计量；出港、曲率/超空间和进港按连续质量状态结算，额外燃料与有效载荷自身也会增加消耗。
- 曲率和超空间速度、最佳效率与燃耗曲线属于具体驱动器型号；曲率通常更慢但可直达，超空间通常更快但依赖航道。
- 推荐票价是完全成本加 20%，只作为提示，不覆盖玩家输入。
- 收益预测必须计入既有航线分流、竞争反应、星港时隙和舰船真实可用率。

### 调度与时间

- 舰船、航班、星港时隙和基地资源均使用同一游戏时钟。
- 所有随机晚点、事件和 AI 决策由种子、日期和对象 ID 决定，保证相同存档与操作可复现。
- 飞行中的舰船不能瞬移换线、出售或进入另一基地；变更在完成当前轮转后生效。

### 公平竞争

- AI 与玩家受到相同的资金、船厂交期、星港容量、舰船航程、维护、基地和联程规则约束。
- 难度主要改变 AI 的预测误差、风险容忍度和起始资源，不允许 AI 读取未来需求或绕过容量。
- 重要 AI 行动必须提供可解释原因。

## v0.11 阶段目标（不是交付承诺）

v0.11 阶段计划尝试满足：

1. 玩家能够从至少两个基地组织直飞与转机网络；
2. 四类旅客可在三种舱位、玩家/AI 航司和直飞/转机方案之间自由选择；
3. 星港时隙、舰船轮转、维护、晚点和转机连接在时间上自洽；
4. 每个航班的载荷、燃料、质量、出港、曲率/超空间和进港阶段严格守恒且可解释；
5. 每条航线能解释收入、完整成本、三舱上座率、四类旅客评价和利润变化原因；
6. 至少 5 家 AI 能在相同规则下持续经营 10 个游戏年而不发生明显决策抖动；
7. 固定种子与操作序列能够复现全部市场、AI、延误和财务结果；
8. 批量平衡测试中不存在无条件占优的船体、引擎、驱动器、速度、票价、基地布局或单一航线策略。

即使这些目标全部达成，项目也只完成一次主要系统整合，不自动进入正式版或可交付状态。是否规划正式版本，需要基于内容完整性、稳定性、试玩反馈和剩余设计债务重新评估。

## 明确延期到 v0.11 之后

- 货运、邮运和军用运输；
- 玩家自建跃迁门与完整科技树；
- 舰船内部布局可视化和逐名人员模拟；
- 外交、战争、领土与行星地表经营；
- 实时多人竞争。
