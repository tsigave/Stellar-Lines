# v0.11：系统整合、平衡与稳定化

## 版本目标

阶段性停止引入新的大型经营系统，集中解决跨系统一致性、性能、平衡、教学、存档和可访问性。v0.11 仍然属于开发版本：目标是验证主要经营系统能否形成稳定、可理解的长期循环，并为下一阶段重新评估范围；完成本计划不自动代表达到正式交付条件。

## 1. 跨系统整合

重点验证以下闭环：

- 需求 → 行程选择 → 航段容量 → 收入 → 满意度 → 声誉 → 后续需求；
- 购船 → 船厂交付 → 基地驻扎 → 航线轮转 → 船龄/维护 → 出售；
- 船体/引擎/驱动选装 → 任务载荷与载油 → 分阶段质量变化 → 航时/燃耗 → 航程与利润；
- 班表 → 星港时隙 → 晚点 → 转机衔接 → 改签/赔付 → 财务；
- 基地 → 人员/维护/始发容量 → 航线成本与可靠性 → 网络扩张；
- AI 决策 → 市场变化 → 玩家反馈 → AI 复查与纠偏；
- 联程选择 → 各段容量 → 跨航司收入和责任结算。

任何聚合值都必须可以追溯到明细，任何明细都只能被汇总一次。

## 2. 财务与会计一致性

公司总账至少区分：

- 票款与跨航司结算收入；
- D–³He 燃料、人员、港口、维护、赔付和基地运营；
- 舰船与基地资本支出；
- 折旧、出售损益和融资成本；
- 现金流、经营利润与会计利润。

航线、基地、舰船和公司四层损益需要对平。采购付款、折旧和出售不能重复影响利润；应急燃料只按实际消耗计成本。

## 3. 平衡框架

建立批量模拟矩阵：

- 不同银河规模、拓扑、港口密度和种子；
- 四类旅客占比与经济发展组合；
- 9 个舰船系列、全部子型号、亚光速引擎、曲率/超空间驱动器和辅助模块；
- 直飞、单枢纽、多枢纽和点对点网络；
- 单基地、多基地和远程运营；
- 不同票价、驱动速度、推力、载油、技术停靠、维护与自动更新策略；
- 5–8 家 AI 人格组合；
- 至少 10 个游戏年的长期运行。

需要监控：

- 各船体、引擎、驱动器与完整配置的使用率和投资回收期；
- 航线利润、票价、上座率和取消率分布；
- 星港拥堵与时隙价格；
- 转机占比、误机率和跨航司收入；
- AI 破产率、网络集中度和市场进入/退出频率；
- 玩家常见失败原因和无反馈时间。

不存在所有市场都占优的船型、巡航速度、统一票价、基地布局或单一 AI 人格。

## 4. 目标、难度与长期经营

- 重做新手目标，使其逐步教授定价、调船、时隙、转机和第二基地；
- 达成目标后继续自由经营；
- 提供沙盒、标准经营和高压竞争三种基础模式；
- 难度说明公开列出差异；
- 失败条件包括资不抵债、持续现金流危机和关键基地失去运营能力；
- 失败前提供可操作预警，不因单日随机晚点突然结束长期存档。

## 5. UI 与信息架构

最终一级页面建议：

1. 星图运营；
2. 航线与班表；
3. 舰队与船厂；
4. 基地与星港；
5. 市场与竞争；
6. 公司财务；
7. 通知与事件。

页面共享同一筛选与定位状态：从亏损航线可跳到班表、舰船、星港和受影响 OD；从旅客不满意原因可以直接打开相关价格或晚点设置。

必须完成：

- 新手引导和上下文帮助；
- 可搜索通知中心；
- 键盘操作、清晰焦点与屏幕阅读器标签；
- 色觉友好模式和不只依靠颜色的状态表达；
- 正文以 16px 为主，任何字体不低于 12px；
- 图表对应数据表和单位说明；
- 小屏幕下不隐藏关键经营操作。

## 6. 性能工程

- 日结算、行程搜索和 AI 决策迁移到 Web Worker；
- 世界、路径、班表和预测使用明确版本号缓存；
- 大型星域使用增量更新，不每日重算全部静态关系；
- 为 3、8、16、24 个行星系分别建立性能预算；
- 快进期间仍能取消、暂停并显示阶段进度；
- 长时间运行控制历史数据体积，保留汇总与关键事件。

建议性能目标以主流桌面浏览器为准：默认 8 星系日结算低于 100ms，24 星系复杂网络低于 500ms；超出时必须分帧或在 Worker 中运行，不阻塞交互。

## 7. 存档与迁移

- 从 v0.4 之后每个正式规划版本提供显式迁移器；
- 存档包含模式版本、世界版本和规则版本；
- 提供多槽、自动存档、手动存档、导入与导出；
- 迁移前保留原存档副本；
- 不兼容时给出明确原因，不静默重开；
- 固定种子与操作日志可以用于复现错误。

## 8. 测试与发布

测试层级：

- 单元测试：需求、效用、成本、指数燃耗、火箭推进、质量守恒、容量、转机、时隙和 AI 评分；
- 集成测试：完整旅行、跨航司结算、动态调船、多基地和晚点恢复；
- 确定性测试：同种子、同操作、同结果；
- 长周期测试：10 年无状态损坏、数值溢出和 AI 抖动；
- 浏览器端到端测试：新游戏到第一条盈利航线、转机枢纽和第二基地；
- 视觉回归：关键页面、常见分辨率和中文字体；
- 存档迁移测试：从 v0.7 新物理模型之后的每个受支持版本升级到 v0.11；v0.6.1 及更早存档明确不兼容。

阶段评审前完成版本号、变更记录、第三方许可核对、错误边界、崩溃恢复和可导出的诊断报告。这些工作用于判断项目距离可交付状态还有多远，不等同于发布准备完成。

## v0.11 阶段验收门槛

1. 总体路线图中的八项总体验收标准全部满足；
2. v0.7 新物理基线建立时的全部回归测试及后续新增测试全部通过；
3. 默认和最大推荐星域达到性能预算；
4. 批量平衡测试未发现无条件占优策略或系统性破产；
5. 至少完成一次从新游戏到多基地转机网络的完整人工试玩；
6. 玩家可以解释主要利润变化、旅客流失、晚点和 AI 行动；
7. 存档、导入导出、迁移和崩溃恢复经过验证；
8. 开发构建、生产构建、许可核对、帮助草案和版本说明均可供内部评审。

满足以上条件只表示 v0.11 的整合目标完成。是否进入正式交付阶段，必须在体验完整性、内容量、稳定性和试玩反馈评审后另行决定，不预先绑定任何正式版本号。

## v0.11 评审后的候选方向

- 货运、邮运和客货混合配置；
- 航司联盟、代码共享和常旅客计划；
- 星港扩建投资与基础设施所有权；
- 更细人员、培训和劳动市场；
- 科研、船型改装和自研舰船；
- 更大规模星域和高级地图表现。
