# v0.7：真实目的地、转机与跨航司联程

## 版本目标

让旅客拥有独立于航线的真实起点和最终目的地，并在直飞、同航司转机、跨航司联程、自助转机和不出行之间自由选择。由此使枢纽、班表衔接、网络覆盖和合作航司产生真正价值。

## 1. 真实目的地需求

每名聚合旅客属于一个 OD 市场：

- 起点星港；
- 最终目的地星港；
- 旅客类型；
- 期望出发时间窗口；
- 最高可接受总价和时间；
- 对转机次数与错失衔接风险的容忍度。

需求不再绑定下一航段。旅客乘坐 A→B→C 时，B 只是连接点，C 才是最终目的地。每段航班都分别占用舱位，并在 B 发生下客、上客和转机。

## 2. 候选行程搜索

第一版最多允许两次转机，即一至三段航班。搜索过程：

1. 从起点的实际出发时刻开始；
2. 枚举满足舱位、最短连接时间和最大绕行限制的航班；
3. 剪枝明显劣于已有方案的价格、时间和风险组合；
4. 每个 OD/旅客类型最多保留若干非支配方案；
5. 加入“不出行”后统一进行选择。

默认限制：

- 最多两次转机；
- 总旅行时间不超过理论最快时间的 3 倍；
- 总距离不超过理论最短距离的 2.5 倍；
- 同一星港不能在一条行程中重复访问；
- 每个市场保留最多 12 个候选行程，具体数量通过性能测试校准。

## 3. 转机时间与枢纽质量

基础最短连接时间：

| 星港等级 | 受保护联程最短连接 | 自助转机最短连接 |
|---|---:|---:|
| 1 | 4.0 小时 | 7.0 小时 |
| 2 | 3.5 小时 | 6.0 小时 |
| 3 | 3.0 小时 | 5.0 小时 |
| 4 | 2.5 小时 | 4.0 小时 |
| 5 | 2.0 小时 | 3.5 小时 |

拥堵、不同航站区、安检、行李重托和事件会增加连接时间。基地与枢纽升级可缩短同航司或合作航司的连接时间。

连接质量至少考虑：

- 计划等待时间；
- 到达航班准点分布；
- 下一班替代服务频率；
- 是否受保护；
- 是否需要重新托运行李；
- 航司与星港的转机声誉。

## 4. 旅客选择直飞或转机

候选行程效用包含：

```text
总票价
+ 门到门旅行时间
+ 出发时刻偏差
+ 每次转机固定惩罚
+ 连接等待
+ 错失衔接期望损失
+ 舱位与服务体验
+ 航司声誉和准点率
```

四类旅客的差异：

- 商务：最重视总时间、班次和连接可靠性；
- 休闲旅游：愿意用一次合理转机换取低价或更好体验；
- 廉价：价格优势足够时可以接受两次转机和自助转机；
- 高端：偏好直飞或高可靠的受保护联程，强烈厌恶错失衔接和降舱。

直飞不保证胜出；足够便宜、班表更好或服务更佳的转机方案可以竞争。

## 5. 同航司转机

玩家默认可以在自己的航班之间销售受保护联程：

- 全程一次购票；
- 行李直挂；
- 前段晚点导致误机时免费改签；
- 收入按各段内部结算；
- 航线页面同时展示本地客流和转机客流。

玩家可以为枢纽设置最低连接时间、连接波次和最大等待容忍度。过度压缩连接会增加误机，过度拉长则降低行程吸引力。

## 6. 跨航司联程与自助转机

公司层面新增联程协议：

- 双方同意后，服务可组合为受保护行程；
- 双方共享必要的班表、舱位和延误信息；
- 收入按各段独立票价权重与距离进行比例分配；
- 误机成本按照导致延误的责任段和协议规则分摊；
- 玩家可以限制开放舱位、市场或合作航司。

没有协议的航班仍可组成自助转机，但：

- 最短连接时间更长；
- 行李需要重新托运；
- 误机不受保护；
- 风险惩罚更高；
- 各航司只获得自己航段的票款。

在 v0.9 智能 AI 完成前，AI 使用规则化的联程接受策略，确保玩家能够测试跨航司网络。

## 7. 收入、容量与延误结算

- 旅客每乘坐一段就占用该段对应舱位；
- 同一航班本地客、转机客和跨航司客共同竞争容量；
- 先完成全行程选择，再按瓶颈航段容量迭代分配；
- 被某一段拒载后，旅客可以改选其他完整行程或不出行；
- 延误发生后重新判断连接，生成改签、住宿、退款和满意度影响；
- 不能把只完成前半段的旅客当作成功抵达最终目的地。

## 8. UI 范围

- 新增 OD 市场浏览器，显示真实起点、最终目的地和四类需求；
- 航线详情区分本地客、转机流入、转机流出和跨航司客流；
- 行程比较器展示直飞/转机的价格、总时间、等待、风险和承运航司；
- 地图可高亮旅客完整行程，而非只高亮单条航线；
- 公司页增加联程协议、收入结算与误机责任记录；
- 枢纽页显示连接波次、最短连接时间和错失衔接率。

## 性能策略

- 理论最短路径和可达性按世界版本缓存；
- 航班时刻变化后只重建受影响时窗；
- 使用非支配剪枝和候选数量上限；
- 市场可以按需求规模分批结算；
- 为迁移 Web Worker 保持纯数据输入输出，不在搜索层依赖 React 状态。

## 本版本不包含

- 玩家建设第二基地；
- AI 自主谈判复杂联盟；
- 代码共享、联盟品牌和常旅客计划；
- 超过两次转机的超长行程。

## 验收标准

1. 旅客记录真实最终目的地，转机星港不会被误认为旅行完成；
2. 同一 OD 至少能同时比较直飞、同航司转机、跨航司联程和不出行；
3. 每段容量严格守恒，转机旅客会占用所有实际乘坐航段；
4. 跨航司票款总和严格等于旅客支付票款，不能重复计收；
5. 前序晚点能够造成可复现的误机、改签和赔付；
6. 航线与星港页面能解释本地客和转机客的来源；
7. 在目标规模银河中，一日结算性能保持可玩，并有基准测试防止组合爆炸。
